G1: wide windows use their space; Run frame stays the same
Goal: at 1920x1080 and 2560x1440, Library, Compare, Settings and Run no longer leave large dead areas, and the Run layout does not change shape between idle, ready and running. Not doing: removing any control; new features; changing the run flow. Limits: view layer only; one primary action per view; layout shift at most 0.05 when a run starts. Work: (1) At 1600 px and wider, let content use the main area: Library as a wider table with the detail or preview beside it where the existing data allows; Compare with the table and the summary side by side; Settings in two columns of grouped sections. (2) Run: the chart frame (the sheet) has the same position and size in idle, ready and running; the right column keeps the same width in all three states (within 8 px) and, while running, shows the trial list from data the UI already receives instead of shrinking to a stub. Acceptance checks (new e2e file `app/e2e/p4-wide.spec.ts`, sizes 1920x1080 and 2560x1440):

* On Library, Compare, Settings and Run, the union of content blocks inside `main` covers at least 65 % of the main area's width.
* On Run, the sheet's bounding box differs by at most 2 px between idle, ready and running; the right column's width differs by at most 8 px.
* A `layout-shift` PerformanceObserver records at most 0.05 across starting a run.
* Axe zero violations on these screens at both sizes in light and dark; `cd app && pnpm typecheck && pnpm lint && pnpm test && pnpm e2e` exit 0; `bash .ui-overhaul/frozen-check.sh check` prints `frozen-check OK`. Done when: checks pass, before and after screenshots (full size, not a contact sheet) in `.ui-overhaul/review4/g1/`, one commit. Open question and default: if the trial list needs data the UI does not receive, show the run plan summary instead and log the request.
